# Analytics and search verification — 22 October 2026

## Current scope

The owner selected Vercel Analytics. The package is installed and `components/Analytics.tsx` mounts the provider only on `jayant.codes`, excluding isolated previews. It strips query strings and fragments before dispatch. Conversion helpers in `lib/analytics.ts` send fixed event names and sanitized primitive properties. Contact form contents are never passed to those helpers. This is a technical description, not a legal-compliance certification.

Vercel Web Analytics was enabled through the existing project API on 22 October 2026. Browser receipt of the deployed script and events must be checked after deployment. Custom-event availability depends on the hosting plan. Unit-test dispatch does not establish dashboard delivery or real traffic.

The owner confirmed Search Console ownership verification and successful sitemap submission. Their screenshot confirms an indexing request was accepted into the crawl queue. It does not prove that Google has indexed the page, establish a ranking, or provide field Core Web Vitals.

## Repeatable checks

- `pnpm verify:analytics` tests property sanitization, duplicate suppression, helper dispatch and SSR safety.
- `pnpm verify:release <baseUrl>` runs the candidate checks and writes evidence under `audit-results/` or `AUDIT_OUTPUT_DIR`.
- In the deployed browser, verify the insights script loads and a non-sensitive event is accepted. Verify the same event in the Vercel dashboard before claiming end-to-end analytics verification.
- Check URL Inspection after Google crawls the site. Record its selected canonical and indexing state separately from the indexing request.

## Remaining external evidence

Real traffic, conversions, search impressions, crawl coverage, ranking and 28-day field performance cannot be generated by a local test suite. Report them as unavailable until the respective dashboard provides data.
